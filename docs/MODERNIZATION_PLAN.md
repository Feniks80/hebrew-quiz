## 2. Факты, проверенные по коду

1. **APK подписывается новым debug-ключом при каждой CI-сборке** (`android-app/app/build.gradle:21`, `versionCode 1` жёстко в `:13`). Обновить приложение поверх установленного нельзя, только удалить и поставить заново. Вместе с приложением пропадает localStorage, то есть прогресс.
2. **Баг TTS-моста.** `TtsBridge.speak()` имеет тип `void` и тихо выходит, если `!ttsReady` (`MainActivity.java:111-112`). JS после вызова сразу делает `return` (`block_template.html:152`), так что Web Speech и MP3 не запускаются. В итоге первое нажатие и устройства без голоса иврита остаются **без звука**. Скорее всего, это и есть причина жалобы «в приложении иврит не говорит».
3. **Смена origin сбрасывает прогресс.** localStorage привязан к origin: сейчас это `raw.githack.com`, планируется `feniks80.github.io`. Всего 11 разных ключей хранилища (`hz-state`, `he100-state`, `he-block-*`, `hq-prog`, `hq2-prog`, `he-test*`).
4. **Навигация WebView ничем не ограничена** (`new WebViewClient()`, `:61`). Внешняя ссылка (openmoji.org) открывается внутри приложения, и у неё есть доступ к `AndroidTTS`.
5. **Service worker.** Аудио не кэшируется: `<audio>` получает ответы 206, их отвергает `cache.put`, а ошибка заглушена. Варианты `?g=` сохраняются отдельными записями. Stale-while-revalidate показывает новую версию только со второй загрузки.
6. **9 копий `speak()`.** zero/everyday разошлись с шаблоном блоков. `hebrew-quiz-full.jsx` устарел.
7. **12 MB робо-MP3** (espeak), пользователь оценил их как «шум». Но на устройствах без he-TTS это пока **единственный** звук.
8. Все страницы самодостаточны (`fetch()` нигде нет), поэтому работают по `file://` и офлайн. Это нужно сохранить.
9. Ветка `claude/new-session-iflHP` на 23 коммита впереди `main`, обратных изменений 0, так что merge пройдёт fast-forward. Репозиторий публичный, GitHub Pages доступны.

## 3. Фазы

### Фаза 0-A — Звук и безопасность (без переустановки, 1 день)
Все изменения здесь **серверные**, кроме 0-A.1. Установленный APK получает их автоматически, потому что грузит контент удалённо.

- **0-A.1 Починить TTS-мост** (нужна новая сборка APK, но ставится вместе с 0-C):
  - `public boolean speak(...)` возвращает `false`, если TTS не готов или `setLanguage() < 0` (проверять и запасной вариант `iw`);
  - в JS: `if (AndroidTTS.speak(t,l,r)) return;`, иначе переходить к следующему способу;
  - `volatile boolean ttsReady`, кэш текущей локали (не вызывать `setLanguage` при каждом нажатии), `onPause → tts.stop()`.
- **0-A.2 JS-фолбек уже сейчас (серверно):** обернуть вызов моста так, чтобы результат `undefined` (старый APK) при неготовом TTS не блокировал MP3. Например, если `AndroidTTS.isReady()===false` или `!hasLanguage(lang)`, сразу играть MP3. Это можно выкатить немедленно, `isReady`/`hasLanguage` в старом APK уже есть.
- **0-A.3 Экран «Проверка голоса»** — первым экраном хаба, если иврит недоступен: `hasLanguage('he')`, кнопка «Установить голос» (`ACTION_INSTALL_TTS_DATA` в новом APK, в старом текстовая инструкция). Для бабушки это самое ценное изменение.

### Фаза 0-B — Спасти прогресс (серверно, 0,5 дня)
- **0-B.1 Кнопка «Сохранить прогресс»** на хабе в текущей ветке. Собирает все 11 ключей в JSON, затем в base64, показывает в `<textarea>` с кнопкой «Скопировать» (`execCommand('copy')`). Код можно сохранить в WhatsApp или сделать скриншот. Скачивание файлов **не используется**: в WebView нет `DownloadListener` и `onShowFileChooser`.
- **0-B.2 Поле «Вставить код»** — импорт.
- **0-B.3 Для браузера** автоматический перенос: со старого origin `location.replace('https://feniks80.github.io/hebrew-quiz/import.html#'+b64)`. Фрагмент URL не уходит на сервер.

### Фаза 0-C — Единственный ломающий релиз (1–2 дня, включая проверку на реальном планшете)
Всё, что требует переустановки или меняет origin, выходит **одним релизом**, чтобы удалять приложение пришлось ровно **один раз**:
- GitHub Pages (можно включить прямо с ветки, merge не обязателен), `APP_URL` → `https://feniks80.github.io/hebrew-quiz/index.html`;
- постоянный ключ подписи: keystore хранится в GitHub Secrets (`KS_B64`, `KS_PASS`, `KEY_ALIAS`, `KEY_PASS`) и **офлайн-копией у автора**, `signingConfigs.release` читает его из env;
- `versionCode` = `1000 + run_number`, закоммиченный Gradle wrapper;
- **`AndroidStore`-мост** → SharedPreferences: прогресс внутри APK больше не зависит от origin, будущие смены домена его не сотрут;
- ограничение навигации: `shouldOverrideUrlLoading` в обеих сигнатурах (minSdk 21), внешние хосты открываются через `ACTION_VIEW`, `setAllowFileAccess(false)`;
- удобство: `setTextZoom` с учётом системного масштаба, подтверждение выхода по «Назад» на хабе;
- порядок для пользователя: сохранить код (0-B) → удалить старое → поставить новое → вставить код.
- Ветку `claude/new-session-iflHP` **не удалять**, пока у всех не стоит новый APK. На ней должна жить страница-редирект.

### Фаза 1 — Страховочная сетка тестов (0,5 дня, **до рефакторинга**)
Playwright (уже установлен, Chromium в `/opt/pw-browsers`) + `http-server`, в CI `npx playwright install chromium`:
- все страницы открываются без `pageerror` и `console.error`;
- мок `window.AndroidTTS` через `addInitScript`: `speak` вызывается с `'he'` и непустым текстом, при `false` срабатывает фолбек;
- `?g=` фильтрует темы;
- миграция: подложить старые ключи, проверить, что импорт и экспорт дают тот же прогресс;
- офлайн: после первой загрузки `setOffline(true)`, страница открывается.

### Фаза 2 — Консолидация кода (1–2 недели)
- `core/core.js` (TTS-стек, `h()`, хранилище, навигация) подключается через `<script src>`.
- Данные в `data/*.js` как `window.DECKS.x=[…]`. **Не JSON через `fetch`**, иначе ломается `file://`. JSON-схема валидируется в CI.
- Один рушій колод (zero, everyday, 5 блоков), рушій вікторини (B1/B2), рушій тестов. `tools/build_blocks.py` переписать на чтение из `data/`, а не регулярками из HTML.
- Один набор иконок (`images/openmoji` по codepoint). `hebrew-quiz-full.jsx` перенести в `archive/`.
- `lang="he" dir="rtl"` на ивритских элементах.

### Фаза 3 — Единый прогресс (3–4 дня)
- Одно хранилище `hq:v2` (через `AndroidStore` в APK, localStorage в браузере), миграция 11 старых ключей.
- Хаб показывает прогресс по каждой колоде и счётчик «сегодня повторить».
- Для бабушки остаются «знаю / не знаю», без коробок и счётчиков. **Leitner сделать опцией, выключенной по умолчанию**, для B1/B2.
- Персональный план по итогам теста **отложить** до стабилизации 0–3.

### Фаза 4 — Офлайн (1–2 дня)
- Service worker: network-first для навигаций, cache-first для `images/`, `audio/`. Кэшировать по `url.pathname`, без `?g=`. Прекеш аудио отдельным `fetch` без Range. `CACHE_VERSION` из git SHA в CI. Не глушить ошибки `install`.
- Бандл в assets APK (WebViewAssetLoader) **не делать**. Это третий origin, двойной контент, и каждая опечатка потребует нового APK. Вернуться к вопросу, только если SW + `AndroidStore` окажутся недостаточными.

### Фаза 5 — Контент и аудио (постоянно)
- Ревизия переводов носителем: тесты, B2, транслитерация по одной системе ударений. Никуд для A2-блоков.
- **Робо-MP3 удалять только после 0-A.3**, когда у пользователя гарантированно работает системный голос.
- Нейронный TTS (Azure/Edge) при необходимости генерировать **локально** и коммитить результат, без секретов в CI.
- Канал обратной связи: кнопка «Сообщить о проблеме» → готовый текст для WhatsApp или e-mail автору.

## 6. Критерии готовности
- APK обновляется поверх установленного без удаления, прогресс сохраняется.
- На устройстве без he-TTS звучит MP3, на устройстве с голосом звучит живой голос. Тишины нет ни в одном сценарии.
- Внешние ссылки открываются в браузере, не в приложении.
- Одна реализация `speak()`, одна колодная логика, данные отделены от разметки.
- Все страницы проходят smoke-тест в CI при каждом push.

**Разногласие и его разрешение.** По бандлу в APK критик предлагал отказаться от него, рецензент — оставить, если действительно нужен. Решение: бандл **отложен** и будет пересмотрен после фаз 0-C и 4. `AndroidStore` и новый service worker закрывают обе причины, ради которых бандл предлагался: независимость от origin и офлайн.
